GitOps & Argo CD

Learn by changing Git, breaking the cluster, syncing applications, and watching Argo CD reconcile desired state with live state.

What problem does GitOps solve?

🚚 Push deployment

CI builds and then connects to the cluster to deploy.

CI → kubectl/helm → cluster

The deployment system needs cluster credentials and write access.

🧲 Pull deployment

A controller inside the delivery boundary observes Git and reconciles the cluster.

Git ← watch/pull → Argo CD → Kubernetes API

Git holds desired configuration; the controller performs reconciliation.

The GitOps loop

Mental model: Git says what should exist. Kubernetes says what does exist. Argo CD repeatedly compares the two and may act based on sync policy.

What Argo CD does

Argo CD is a declarative GitOps continuous delivery tool for Kubernetes. It compares target state represented by Git with live cluster state, reports deviations, and supports manual or automatic synchronization.

flowchart TB
 G[(Git / Helm / Kustomize / YAML)] --> R[repo-server\nrender desired manifests]
 UI[CLI / UI / API] --> S[argocd-server]
 S --> C[application-controller]
 R --> C
 C -->|compare + reconcile| K[(Kubernetes clusters)]
 C --> M[status / health / history]
 N[notifications-controller] --> X[Notifications]
 C --> N

Webhook vs reconciliation timer

A webhook can notify Argo CD about a Git change quickly. Reconciliation still provides the controller loop that compares Git with cluster state.

Remember the switches

OptionWhat it controls
automatedWhether detected desired-state changes can be synced automatically.
pruneWhether resources removed from Git may be deleted from the cluster during automated sync.
selfHealWhether live-cluster drift can trigger automated reconciliation back toward Git.

Application = source + destination + policy

flowchart LR
 SRC[Source\nrepoURL + revision + path/chart] --> APP[Argo CD Application]
 APP --> DST[Destination\ncluster + namespace]
 POL[Project + sync policy + options] --> APP
 APP --> RES[Deployment / Service / ConfigMap ...]

apiVersion: argoproj.io/v1alpha1
kind: Application
metadata:
  name: color-app
  namespace: argocd
spec:
  project: default
  source:
    repoURL: https://example.invalid/platform-config.git
    targetRevision: main
    path: apps/color
  destination:
    server: https://kubernetes.default.svc
    namespace: color
  syncPolicy:
    automated:
      selfHeal: true
    syncOptions:
      - CreateNamespace=true
Application vs AppProject: Application defines what to deploy and where. AppProject provides a logical grouping and can constrain allowed sources, destinations and resource kinds.

Deployment patterns

Mono application

App-of-Apps

A parent Application points to manifests that define child Argo CD Applications.

Multi-cluster

GitOps does not make plaintext secrets safe

The attached training material discusses Bitnami Sealed Secrets and the Argo CD Vault Plugin as approaches for secret workflows.

Sealed Secrets model

Commit encrypted SealedSecret material. A controller in the cluster turns it into a Kubernetes Secret.

Vault/plugin model

Store secret values in Vault and use placeholders in Git. A plugin resolves values during manifest generation.

Rule: do not commit raw passwords, tokens, kubeconfigs, private keys, or unencrypted Kubernetes Secret values to a public repository.
